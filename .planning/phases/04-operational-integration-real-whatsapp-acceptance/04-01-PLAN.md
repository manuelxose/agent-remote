# Phase 4: Operational Integration & Real WhatsApp Acceptance

> **For agentic workers:** execute this plan task-by-task with the existing GSD phase workflow. Each task ends with a runnable verification.

**Goal:** Make the existing Baileys gateway executable from configuration and verify the real WhatsApp-to-Claude/Codex/Copilot path without changing the established runtime boundaries.

**Architecture:** Add one application composition root under `apps/gateway/src` that loads environment/file configuration, registers the existing router, runtimes, adapters, session store, and WhatsApp channel, then owns startup/shutdown. Add a small doctor command over the same configuration and availability checks. Keep unknown-route diagnostics and operational logging at the gateway/application boundary.

**Tech Stack:** Node.js 24, TypeScript/NodeNext, existing npm workspace, Baileys, Node standard library, `qrcode-terminal` for terminal QR rendering.

- Preserve Phases 1–3 and all existing runtime/channel contracts.
- Do not add a second router or replace Baileys.
- Never put secrets, real WhatsApp IDs, or credentials in Git.
- Keep direct executable/argv process execution and approved-workspace enforcement.
- Unavailable CLIs remain `FAIL`/`UNAVAILABLE`; never fake E2E success.
- Run `npm run build`, `npm test`, and `graphify update .` after implementation.
