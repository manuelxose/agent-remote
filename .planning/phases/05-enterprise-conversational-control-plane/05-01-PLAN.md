# Phase 5 Plan: Enterprise Conversational Control Plane

**Goal:** Replace the transitional WhatsApp command path with a durable,
channel-neutral control plane for managed conversations and developer agents.

**Plan source:**
`docs/superpowers/plans/2026-09-11-enterprise-conversational-control-plane.md`

## Execution order

1. Neutral contracts and atomic versioned persistence.
2. Command registry, state machine, authorization, and dispatcher.
3. Per-session queue, idempotency, cancellation, model policy, and runtime seams.
4. Composition-root and WhatsApp integration.
5. Documentation, GSD verification, Graphify refresh, and real acceptance.

The composition root also enables a configurable per-identity/conversation
rate limit; the default is 60 inbound messages per minute.

## Verification gate

The phase remains incomplete until build, full tests, doctor, Graphify refresh,
boundary inspection, and available real WhatsApp/provider acceptance are
recorded in `VERIFICATION.md`. Missing external credentials or unavailable
provider CLIs are recorded as `UNVERIFIED`.
