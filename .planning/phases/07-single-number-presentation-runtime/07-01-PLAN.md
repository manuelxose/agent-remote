# Phase 7 Plan: Single-Number Presentation Runtime

The executable implementation plan is maintained at `docs/superpowers/plans/2026-09-11-single-number-presentation-runtime.md` and implements `docs/superpowers/specs/2026-09-11-single-number-presentation-runtime-design.md`.

## Goal

Preserve the one-number WhatsApp architecture while adding typed logical origin metadata, exact bounded generated-message correlation, final-only delivery with delayed progress, and an opt-in Web/Desktop presentation companion.

## Execution units

- [ ] Task 1 — add `MessageOrigin` and logical participant contracts; attach agent origin at control-plane completion.
- [ ] Task 2 — add the bounded `AgentMessageRegistry` and record exact Baileys send IDs.
- [ ] Task 3 — change WhatsApp delivery to composing plus final by default, with one delayed progress message when configured.
- [ ] Task 4 — add the authenticated loopback bridge and deterministic DOM-only companion.
- [ ] Task 5 — update documentation and GSD artifacts.
- [ ] Task 6 — run automated, measured, and real WhatsApp verification; record truthful client-layer status.

## Verification gates

- `npm run build` passes.
- `npm test` passes with zero failures.
- `npm run doctor` reports safe provider, session, delivery, and companion diagnostics.
- `graphify update .` completes after structural changes.
- Real WhatsApp acceptance is recorded separately from fakes and never claims left-side rendering for official mobile.
