# Phase 6 Plan: Real-Time Conversational Runtime

**Goal:** Stream provider output through explicit logical sessions and deliver bounded, natively correlated WhatsApp replies.

**Plan source:** `docs/superpowers/plans/2026-09-11-real-time-conversational-runtime.md`

**Spec:** `docs/superpowers/specs/2026-09-11-real-time-conversational-runtime-design.md`

## Execution order

1. Neutral correlation, execution events, and streaming process contracts.
2. Provider registry, logical resumable sessions, and incremental adapters.
3. Control-plane correlation, telemetry, delivery aggregation, and cancellation.
4. WhatsApp quoted replies, presence, and application integration.
5. Shutdown, diagnostics, benchmarks, documentation, Graphify, and verification.

## Verification gate

The phase remains incomplete until build, full tests, focused streaming and
WhatsApp integration tests, doctor, boundary inspection, Graphify refresh,
benchmark evidence, and available real WhatsApp/provider acceptance are recorded
in `VERIFICATION.md`. Missing external credentials or provider CLIs are
recorded as `NOT LIVE-VERIFIED`/`UNVERIFIED`, never as success.
